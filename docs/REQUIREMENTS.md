# TYPE SCANNER ─ 要件定義書

## 1. プロダクト概要

高校 eスポーツコース「メンタルコミュニケーション」授業（60分）で利用する、オールインワン授業進行アプリ。Kahoot や外部スライドを使わず、本アプリ単体で授業全体が完結する。

- **対象授業時間：** 60分
- **想定同時参加者数：** 80〜100名
- **対象ユーザー：** 講師（PC大画面）と生徒（スマホ／PCブラウザ）
- **本番ドメイン：** `rune-type6.*.workers.dev`

## 2. 最重要設計方針

1. アプリ単体で60分授業が成立する（Kahoot・外部スライド不要）
2. 80〜100名同時参加に耐える（診断処理は各端末で完結、サーバーへは結果のみ送信）
3. 個人情報を保存しない（名前入力なし、匿名sid、DB不使用、揮発のみ）
4. 断定しない診断（「あなたは〇〇な人」ではなく「今日の回答では〇〇の傾向」）
5. 講師が完全にペースを管理する（生徒は先回り不可、Kahoot式同期）
6. 途中離脱・スマホ暗転からの復帰対応（localStorage + sid再利用）

## 4. ステージ（フェーズ）構成

```
[lobby]
  → [stage0_rules] → [stage0_theme] → [stage0_flow]
  → [stage1_active] → [stage1_results]
    → [stage1_explain_1..4]       # コンペティター→アチーバー→ソーシャライザー→エクスプローラー
  → [stage1_bridge]
  → [stage2_active] → [stage2_results]
    → [stage2_explain_1..4]       # アタッカー→ガーディアン→アナリスト→ブースター
  → [stage3_summary] → [stage3_share] → [stage3_comment] → [stage3_wordcloud] → [stage3_closing]
  → [closed]
```

遷移はすべて講師の「次へ」ボタンで実行。生徒は先回り不可。

## 5. データ要件

### 5.1 タイプ定義

- **ワーク1（ゲーマータイプ）：** competitor / achiever / socializer / explorer
- **ワーク2（危機対応タイプ）：** attacker / guardian / analyst / booster
- **特例：** balanced（4タイプすべてが ±2点以内）

### 5.2 スコアリング規則

1. 各設問の選択肢には1タイプが対応。選択で +1点
2. 20問回答後、4タイプ合計20点になる
3. メインタイプ = 最高スコアのタイプ
4. サブタイプ = 2位のタイプ
5. **同点処理：** タイプID昇順で若い方をプライマリ。もう一方は「同程度の傾向」として併記
6. **バランス型：** 最大-最小 ≤ 2 のとき mainType = `balanced` で特別カード

### 5.3 設問・タイプ解説・16パターン

| ファイル | 内容 | 状態 |
|---------|------|------|
| `src/data/work1Questions.ts` | ワーク1 20問 | 構造のみ用意、本文は別途投入 |
| `src/data/work2Questions.ts` | ワーク2 20問 | 同上 |
| `src/data/typeInfo.ts` | 8タイプ解説 | 同上 |
| `src/data/comboAnalysis.ts` | 16パターン＋バランス型 | 同上 |

## 6. 通信プロトコル（要旨）

詳細は `shared/protocol.ts` および ARCHITECTURE.md を参照。

### Client → Server

`T_CREATE_ROOM`, `T_NEXT_PHASE`, `T_END_ACTIVE`, `T_CLOSE_ROOM`, `T_SET_DISTRIBUTION_VIEW`, `S_JOIN`, `S_WORK_RESULT`, `S_COMMENT`, `REACTION`, `PING`

### Server → Client

`ROOM_CREATED`, `JOINED`, `STATE`, `PHASE_CHANGE`, `PROGRESS`, `WORK_DISTRIBUTION`, `CROSS_MATRIX`, `COMMENT_CLOUD`, `STUDENT_COUNT`, `REACTION_BURST`, `ERROR`, `PONG`

## 7. クラス設定

デフォルト：`["梅田第1", "梅田第2", "梅田7F", "名古屋", "岡山"]`

## 8. 非機能要件

| 項目 | 要件 |
|------|------|
| 性能 | WebSocketメッセージ < 1KB／件、DOメモリ < 1MB／ルーム |
| 同時接続 | 1ルームで 100クライアント以上 |
| 復旧 | sid 再接続でフェーズ追従、回答途中も localStorage で復帰 |
| 端末対応 | 生徒：スマホ 375px〜 / PC 1024px〜 ／ 講師：PC 1280px〜 |
| アクセシビリティ | 最低限のコントラスト確保、文字サイズ可読 |
| セキュリティ | 個人情報・端末識別子を一切収集しない、Cookie/トラッキング無し |
| 永続化 | DB 不使用、Durable Object のメモリのみ。授業終了で破棄 |
| デプロイ | `wrangler deploy` 1コマンド／GitHub Actions（main push 自動） |

## 9. 注記テキスト（必須掲載）

### 9.1 診断の位置づけ
> このアセスメントはBartle分類およびストレスコーピング理論を参考にしていますが、学術的な心理検査ではありません。チーム活動での自分の傾向を振り返るための教育ツールです。

### 9.2 ワーク2冒頭
> ここからはチームでのピンチ場面を想像して答えてください。チーム経験がなくても大丈夫。『もしそうなったら自分はどうするかな？』と想像しながら、直感で選んでOKです。

### 9.3 ブリッジ
> ワーク1では『普段のゲームとの向き合い方』を見ました。次のワーク2では『チームでピンチの時にどう動くか』を見ていきます。2つを掛け合わせることで、あなただけのプレイヤータイプが見えてきます！

## 10. 受け入れ基準（DoD）

- 講師が一気通貫で60分の授業を進行できる
- 100端末同時参加でも UI が破綻しない
- 生徒の暗転 → 復帰でフェーズと回答が保持される
- 個人情報を一切送受信しない（DevTools で確認可能）
- `wrangler deploy` で本番反映、GitHub Actions が main で自動実行
